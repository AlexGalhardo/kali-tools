## Baseline and test-first evidence

Baseline: 31 Playwright workflows; wifi 77.3%, app 94.7%, contract 100%, wailsui 99.3%, cli 88.1%, httpapi 89.1% statement coverage.

The consent/reveal tests first failed with undefined mapping/decision functions. Observation tests first failed on missing `WithObserved`. Contract tests failed on missing `SettingsURI`. Opener tests failed on missing runtime field and binding method. CLI human-output tests failed on the missing settings hint. The browser test first showed the old generic consent error, then exposed StrictMode's duplicate initial query; the final guarded query runs once until explicit retry.

`TestCLIWiFiConsentRevealDoesNotPrintProviderKey` then failed with `error response leaked provider key`: the synthetic provider returned a value together with a consent error. The application now discards Wi-Fi values on errors, protecting every adapter. This is the QG-11 scope correction recorded in the spec. Successful metadata/reveal output remains unchanged.

- Preserve completed H05/C01/W01 contracts instead of the spec's historical paths, desktop-only reveal restriction, bare HTTP error example or exit 1. Consent uses the established exit 4 and the existing nested HTTP error envelope. Opener injection uses the existing `Runtime` pattern as `OpenURL`.
- Add catalog/busy props to the notice; select transport with `transportKind()` because `connected()` also covers HTTP. No visual redesign or new dependency.
- The project-layout skill's old root-facade description predates H05; binding architecture wins, so bindings remain in `adapter/wailsui`.
- WinRT pre-check remains deferred. Access denial on build >= 26100 can also represent policy restrictions; native acceptance must assess ambiguity. No privacy setting or registry value was changed.
- Linux execution/coverage, native consent/reveal/account tests and the pre-existing release-version mismatch remain open. A06 is the next spec after applicable A05 gates are satisfied; it was not started in this group.
