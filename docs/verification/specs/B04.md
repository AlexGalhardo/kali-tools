# B04 connection inventory and throughput evidence

- Date: 2026-10-23. Host: Linux, Go 1.27.3.
- Status: Linux `/proc` socket-to-process mapping, a bounded `127.0.0.1` exchange, and an iperf3 `-J` parser are implemented. Windows and macOS mapping return `unsupported`. No release tag was created.

## What was verified

A fixture `/proc/net/tcp` row whose inode is owned by pid 42 and process `fixture` is reported as `127.0.0.1:8080` to `192.0.2.10:443`, state `established`. An inode with no owner is omitted. An unreadable process fd directory is skipped. An unreadable socket table is `permission_required`. A missing socket table is `unsupported`. The JSON has no interface counter and no rate.

`Exchange` for 50ms returns an endpoint on `127.0.0.1`, `duration_ms` 50, a non-zero byte count and source `kali-tools`. Cancelling a 10s exchange returns `context.Canceled`. Durations outside 1ms..10s are rejected. The listener is loopback only.

`ParseIperfJSON` reads `end.sum_sent.bytes` (4096) and `start.connecting_to` (`192.0.2.10:5201`). `bits_per_second` 999999 is not copied. iperf3 is not executed. The exchange is not iperf3-wire-compatible.

`GET /api/connections`, `POST /api/throughput`, `connections`, `throughput --duration` and `throughput --iperf-json` use the same use cases. Wails `Connections` and `Throughput` return the contract DTOs.
