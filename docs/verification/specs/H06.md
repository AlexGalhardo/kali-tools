## Deviations and follow-ups

- The H05 implementation already carries job sequence numbers. H06 preserves them; it does not add a second wire change.
- A directory is already rejected with a domain `invalid_input` before reading. The unknown OS-error CLI test therefore uses a nonexistent capture file in a temporary directory. It proves the required generic failure and path redaction without weakening existing validation.
- DA-5 prohibits constructing domain errors in the driving adapters, while legacy capture decoding must retain recognized codes. The decoder now returns a contract error; `FromError` is idempotent for contract values (validated and sanitized again), with a regression test. Real capture producers retain their original typed errors until the central mapping boundary.
- Updated the existing bootstrap import guard to allow precisely `adapter/contract`; test-only helper and contract test files were also added where the spec's file list omitted them. No production port or capability behavior changed.
- The AST redaction registry uses `os.ReadDir` plus `parser.ParseFile` because `parser.ParseDir` is deprecated in the project toolchain and fails staticcheck.
- Wails generation emits a non-fatal reserved-keyword warning for the spec's `contract.Interface` type and existing time conversion notices. Generation exits 0, generated TypeScript passes strict checking and the Go type name stays as specified. Native IPC remains unverified.
- Binding generation uses isolated `APPDATA=build/bin/h06-bindings-appdata`, avoiding the known eager-bootstrap default database side effect from H05.
- Impeccable context reported stale design sidecar metadata and a newer skill version; neither was changed as part of this DTO/error spec.
