# B05 capture resilience evidence

- Date: 2026-10-23. Host: Linux, Go 1.27.3.
- Status: truncation reporting, IPv6 hop-by-hop decode, and the no-reassembly rule are implemented. Corrupted input, export disk-full, Pktmon cancel, and a provider interface-loss error are covered by tests. Pulling a cable was not run. No release tag was created.

## What was verified

`Decode` marks a packet truncated when the original length exceeds the captured bytes, when `CaptureLength` is smaller than the original length, or when gopacket reports an error layer. A truncated DNS summary does not include the question name. A complete IPv6 hop-by-hop header is followed through to ICMPv6. An IPv6 fragment is not decoded as UDP and its payload is not copied into the summary. Two TCP segments are not joined, so a later segment is not treated as the continuation of an HTTP request. HTTP recognition still uses only the first 8 bytes of one segment.

Import rejects a short buffer, a truncated file header, and a record whose captured length is greater than its original length. `Artifact.Write` returns `ENOSPC` from the writer for both pcap and pcapng. `Artifact.Add` already stops at 10000 packets and at the reserved 64 MiB budget. Live Windows capture sets `Limited` and stops when `Add` fails; that file is not executed on Linux.

`TestPktmonCancelAlwaysStops` stops a started Pktmon session on cancel and does not put `private-payload` in the error. `TestPktmonStatusAndEarlyFailures` rejects a temporary-directory failure before start and does not echo `private-path`. `TestCaptureInterfaceLossStaysOutOfHistory` records `failed: capture interface disappeared` and keeps `synthetic-psk` out of the history summary.

TShark is not executed. [ADR 006](../../adr/006-native-service-inspection.md) keeps it inventory-only. Supported levels are in [capture decoding](../../capture-decoding.md).
