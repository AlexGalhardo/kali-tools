## Review, deviations and follow-ups

- H01/H02 native acceptance stays pending under the owner's explicit continuous headless instruction. H03 follows their verified implementation contracts.
- Type aliases would create an app/tools or app/storage import cycle if applied before removing app's concrete imports. Therefore the alias and port transition was made atomically rather than leaving the intermediate states of spec steps 1-4 compilable. Final dependency assertions pass.
- H03's file list omitted `internal/bootstrap/bootstrap_test.go` and `internal/adapter/storage/storage_test.go`, but section 8 requires extending their tests. Updated bootstrap accesses through Service.History, extended cleanup/provider checks, and added the required legacy JSON test there.
- Moving Settings and HostAdapter to app makes their aliases external structs for go vet. Changed three Settings literals to keyed fields (one in storage, two in existing tests), and one HostAdapter literal in platform_linux.go. This is the sole mechanical OS-file change required despite section 4.3's unchanged-OS-files intent; assertions, values and SQL remain unchanged.
- Service.Close no longer owns SQLite. Real-store tests close it themselves; the restart test explicitly closes its first store before reopening. Its original persistence assertions remain unchanged. Bootstrap closes service then store exactly once.
- Mutation review: replace the settings port SaveSettings call with a no-op; `TestDiagnosticJobWithFakes` fails because settings remain `{en 30}`. Restore source and repeat race tests: pass.
- XML parser tags on application-owned Nmap types are the explicit H03 transition, separated further in H06. Contract suites remain H07; no extra dependency or domain/OS split introduced.
- Native acceptance remains open; builds, parser tests and headless browser tests do not prove hardware behavior.
