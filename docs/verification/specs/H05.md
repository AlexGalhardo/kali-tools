## Review, deviations and follow-ups

- The pre-H02 H05 draft omitted seq from its legacy job payload and AC-9 despite requiring unchanged payloads. Updated that draft to preserve the already-shipped H02 field; tests check the existing schema_version/seq/job/result shape.
- CLI capture keeps a background-owned subscription from H04 so cancelling the caller does not close the channel before its completion event. On cancellation it stops once and waits at most 5 s, then returns the caller error. Typed capture errors are preserved; only a missing typed error falls back to the legacy string parser.
- Startup also opts into app.StartMetrics, preserving H04 behavior; Shutdown only owns the binding forwarder. Application/store cleanup remains in the root after wails.Run.
- Desktop main retains H01's normal console signal behavior instead of adding the draft's signal handler, which would intercept Ctrl-C without instructing Wails to quit. CLI signal handling is unchanged and still cancels before os.Exit.
- Native smoke setup moves its context/timer initialization to OnDomReady so OnStartup and OnShutdown can be direct binding method values; this prevents lifecycle methods leaking into the generated frontend API. Original IPC assertions are retained with only the namespace update.
- Added test-only export helper files and moved the H04 capture tests, omitted from the older H05 file list. No extra production API was added. A root-local runWithBootstrap function makes startup/cleanup error paths testable without global injection or new environment variables.
- Updated existing bootstrap source checks for removed app.go and for flag parsing in precisely the CLI driving adapter. Environment reads remain forbidden throughout internal, and inner-package adapter imports remain forbidden. This adapts the prior checks to the authorized H05 extraction rather than disabling them.
- Optional wailsui/Bindings members in Window.go require non-null assertions at the already-installed Playwright fake overrides. The change is mechanical; no workflow assertion or frontend exported API changed.
- SaveCapture intentionally opens a valid-format save dialog before a missing artifact is rejected, as explicitly accepted by H05. Invalid format is still rejected before any native dialog.
- Provider-state transport tests inject a bounded fake capture provider; they do not sniff live host traffic and make no hardware acceptance claim.
- Known follow-up from H05: eager desktop bootstrap also executes during Wails binding generation. Regeneration in this task sets APPDATA to ignored build/bin/h05-bindings-appdata so real user preferences/history are untouched; a bindings-mode startup guard remains follow-up work per the spec.
- Mutation review: invert the save-format guard. `TestSaveCaptureValidatesFormatBeforeDialog` fails with error=nil. Restore source; repeated race suites and lint pass.
- No release created and no remote CI wait performed. Native acceptance remains open.
