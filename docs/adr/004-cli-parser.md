# ADR 004: CLI argument parser

Status: proposed; follows the specified stdlib decision rule, pending owner ADR approval.

Context: the H05 parser uses stdlib `flag`, dispatches on `args[0]`, and creates one `FlagSet` per invocation (`internal/adapter/cli/cli.go:32-40`). PLAN §7.1 requires 16 top-level commands: version, doctor, capabilities, interfaces, inventory, neighbors, diagnose, discover, inspect, wifi, capture, jobs, history, settings, tools and serve. Diagnose has 6 leaf commands, Wi-Fi 2, capture 3, jobs 3, history 2 and settings 2; maximum depth is 2. Global flags are `--json`, `--timeout`, `--no-color` and `--lang`. `rg -n -i 'completion' PLAN.md docs/brainstorming.md` returns no matches; shell completion is not a requirement. Architecture research §7.2 asks for re-evaluation beyond about six subcommands or when completion is required; this ADR performs that review.

Options: (a) retain stdlib `flag`, with a command table in `internal/adapter/cli`, one `FlagSet` per leaf, a helper registering global flags on every set and help generated from the table; (b) adopt Cobra on pflag. Candidate pins verified through `go mod download -json` on 2026-10-21 are `github.com/spf13/cobra v1.10.2`, `github.com/spf13/pflag v1.0.10` and Windows transitive `github.com/inconshreveable/mousetrap v1.1.0`. Their downloaded license files identify Apache-2.0, BSD-3-Clause and Apache-2.0 respectively. Cobra's go.mod requires pflag v1.0.9; an explicit v1.0.10 pin would raise it under MVS. Documentation-only module requirements would need notice review too if imported. Adoption would require owner approval for the dependency, an updated docs/dependencies.md inventory, and verification that scripts/notices.mjs collects all new module licenses. None is added by this ADR.

Decision: choose stdlib `flag`. The binding rule chooses Cobra if and only if PLAN requires shell completion, nesting deeper than 2, or syntax that stdlib cannot express. None applies: C01 explicitly excludes completion, keeps depth 2, and does not require POSIX flag interleaving. Command count alone justifies this review but does not override that rule.

Consequences: C01 implements the command table, per-command help, documented exit codes and `--json` on every command. No generated shell completion is provided. Go-style single-dash flags remain accepted; flags precede positional arguments according to each leaf's documented syntax. No new parser dependency or runtime library is introduced.

Revisit when shell completion enters PLAN, a command requires depth 3, more than 40 leaf commands exist, or users require POSIX flag interleaving. The repository owner decides; record any replacement in a superseding ADR before changing the public CLI contract.
