# kali-tools 0.1.0-alpha.2-dev

Unsigned development preview of the Windows-first local network toolkit. This draft is **not** a qualified alpha release. See [the delivery plan](https://github.com/AlexGalhardo/kali-tools/blob/main/PLAN.md), [the changelog](https://github.com/AlexGalhardo/kali-tools/blob/main/CHANGELOG.md) and [the architecture](https://github.com/AlexGalhardo/kali-tools/blob/main/docs/architecture.md).

## What changed since 0.1.0-alpha.1-dev

- **Architecture.** The repository is reorganized into a hexagonal (ports and adapters) layout:
  - driven adapters live under `internal/adapter/`;
  - the frontend is split into `app/`, `shared/` and `features/`;
  - setup entry points live under `scripts/setup/`.
- **Network port.** `internal/network` no longer imports an adapter. Native ICMP is injected through the `network.Prober` port.
- **Reliability.**
  - A full event buffer no longer drops terminal job states; they wait up to 2 s for delivery, so the UI cannot get stuck in "running".
  - Service shutdown is idempotent.
  - The 64-bit Windows ICMP option layout is corrected.
  - The Linux inventory no longer returns `null` gateway lists.
  - DNS names with underscores (for example `_dmarc`) are accepted.
- **Formatting.** gofmt -s and goimports are enforced by golangci-lint and a Lefthook pre-commit hook.
- **Documentation for contributors and agents:**
  - Clean/Hexagonal architecture research;
  - binding architecture reference;
  - deepened tools research (Nmap NPSL, Npcap redistribution, Windows 24H2 Wi-Fi location consent, Pktmon);
  - Spec Driven Development specifications with auditable quality gates;
  - project agent skills.

## Downloads

- Windows x64 ZIP: desktop EXE and CLI EXE. Requires Windows 11 with Edge WebView2.
- Linux x64 tar.gz: desktop and CLI. Requires Ubuntu 24.04 with GTK3/WebKitGTK 4.1.
- macOS x64 ZIP: Intel app bundle and CLI.
- macOS arm64 ZIP: Apple Silicon app bundle and CLI.
- Source archive, dependency inventory, third-party notices and `SHA256SUMS`.

Builds come from native GitHub runners after the quality, security, browser and Docker checks pass. Each native archive includes `BUILD.json` with its source commit, version, platform and architecture. Verify the SHA-256 checksums before running anything.

## Included

- Interface inventory and traffic counters.
- DNS record queries.
- TCP/HTTP/TLS diagnostics.
- Windows IPv4 ping and traceroute.
- Scoped discovery.
- Optional Nmap service signatures.
- SQLite preferences and history.
- PT-BR/English UI.
- Bounded PCAP/PCAPNG import and export.

The web server and the complete CLI are specified (`docs/specs/`) but not yet implemented.

## Limits

- **Windows hardware acceptance is open.** Wi-Fi key reveal and live capture still need hardware and permission acceptance.
- **Live capture.** Raw capture is IPv4-only, has no kernel drop count and requires administrator authorization.
- **Wi-Fi consent.** Windows 11 24H2 may deny Wi-Fi metadata until location consent is granted. Explicit handling is specified in A05.
- **Key display.** Key display is explicit and transient.
- **Saved packet files.** A saved packet file includes the retained payloads. Ordinary history excludes secrets, targets and payloads.
- **Linux/macOS.** Wi-Fi and capture providers and full native acceptance are incomplete. Packaging success does not establish feature parity.
- **External tools.** Nmap and TShark are installed separately. The NPSL position for the Nmap adapter awaits an owner decision.
- **Not yet in place:** performance budgets, installers, signing and notarization.

## License and signing

Project code uses the MIT license. Third-party components keep their own notices. The binaries have no trusted code signature, and the macOS previews are not notarized. The draft workflow does not create a release tag or a qualified release.
