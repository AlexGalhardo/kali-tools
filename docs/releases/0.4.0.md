# kali-tools 0.4.0

Published at the owner's explicit checkpoint request on 2026-10-21. **Unsigned development preview; full PLAN and release qualification remain open.**

## Changes

- Shared desktop/browser styling now uses a black workspace, neon green accents, bundled offline JetBrains Mono and responsive navigation. Impeccable review and 19 browser workflows cover the theme. The HTTP transport itself remains pending.
- H07 native Wi-Fi, ICMP, host inventory and elevated capture contracts pass on the owner's Windows PC. Capture tests now choose an active interface.
- Hosted Windows/macOS failures corrected; all jobs passed in [S09 verification](https://github.com/AlexGalhardo/kali-tools/actions/runs/39668017937).
- Eight architecture dependency rules now run in hooks and CI. [Positive hosted proof](https://github.com/AlexGalhardo/kali-tools/actions/runs/39669810016) passes; an isolated negative PR failed on the expected rule and was closed without merging.
- C01 steps 1–4 add strict per-command flags/help, capabilities/tools, jobs/history/settings, confirmed key reveal and canonical capture conversion. History acceptance runs through direct, CLI and Wails without a skip.

## CLI compatibility

JSON **remains the default** in this checkpoint. Use `--json` explicitly in scripts. Flags unrelated to a command are now rejected. Invalid flag values are not echoed. Help exits 0.

Exit codes: 0 success, 1 generic failure, 2 invalid input, 3 unsupported, 4 permission/location consent, 5 dependency missing, 6 not found, 7 timeout, 8 conflict, 9 authentication and 130 cancellation. Scripts that previously treated every operation failure as exit 1 must account for the new statuses. This pre-1.0 change is the reason for a minor version increase.

Prefer `diagnose tcp`, `wifi show`, `capture live`, `capture import` and `capture export`. Existing aliases remain accepted with a deprecation warning. `wifi reveal --confirm` explicitly prints the saved key after a warning; terminal recordings can retain it. Secrets and packet payloads do not enter ordinary history.

## Limits and open work

The CLI still composes an in-memory store: its history/settings do not survive process exit, and it cannot cancel jobs from another process. Human/progress rendering, job-backed CLI diagnosis, persistent composition, SSH acceptance, complete schema freeze and C01's final coverage gate remain pending. `serve` is only a reserved help/error stub and opens no listener; W01/W04 remain unimplemented.

The full PLAN is not complete. Linux/macOS hardware qualification, Windows consent variants, capture backend research, performance budgets, Nmap license decision and trusted signing/notarization remain open. Downloaded executables are unsigned development artifacts, not production-qualified releases.
