# kali-tools 0.3.0

Published at the owner's explicit request on 2026-10-21. Binaries are **unsigned development builds**. This version number does not close native hardware, performance, signing or platform acceptance gates in [PLAN.md](https://github.com/AlexGalhardo/kali-tools/blob/main/PLAN.md).

## Changes

- Shared application composition, consumer-owned ports and one application facade for the CLI and Wails GUI (H01–H04).
- Extracted CLI and Wails adapters, shared transport DTOs and safe error mapping (H05–H06).
- Real/fake port contract suites and shared headless acceptance drivers (H07).
- ICMP targets now validate before DNS/native delegation; the previously failing real contract passes.
- Reconciled PLAN checklists, SDD statuses and the next implementation step: H08/H09.
- Installed and verified the Windows development toolchain, including GCC for race detection.

## Verification

Go tests, race checks, formatting, lint, host/desktop/Linux/Darwin vet, core/desktop vulnerability scans and frontend typecheck/lint/build passed. All 18 Playwright workflows passed. Binding regeneration produced no drift. See [H07 evidence](https://github.com/AlexGalhardo/kali-tools/blob/main/docs/verification/specs/H07.md#continuation-2026-10-21).

## Downloads and limitations

The locally verified package contains Windows x64 desktop and CLI binaries, MIT license, dependency notices and build metadata. SHA-256 checksums and a source archive accompany it. Additional platform artifacts require native CI builds and are not implied by cross-target vet.

Wi-Fi reveal, privileged live capture, native Wails IPC and Linux/macOS hardware qualification remain open. The complete CLI and secure web server are specified but not implemented. Nmap/TShark/Npcap remain separately installed optional tools; the Nmap license decision remains open. No trusted code signing or notarization is provided.

## Release numbering

The two earlier development release records are renamed to v0.1.0 and v0.2.0. Their original source commits, artifact names and contents remain unchanged, including the development version embedded in those binaries; do not interpret the renamed labels as rebuilt artifacts.
