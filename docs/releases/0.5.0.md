# kali-tools 0.5.0

Owner-requested checkpoint published on 2026-10-22. **Unsigned development preview. Full PLAN and native qualification remain open.** Published earlier releases are unchanged.

## Changes

- Human CLI output by default, explicit `--json`, English/PT-BR rendering, persistent history/settings, job progress and cancellation. Scripts must explicitly opt into JSON. Stable exit codes remain those documented in [CLI contracts](../cli.md).
- `kali-tools serve` serves the same frontend as the desktop through authenticated HTTP and SSE. Open its printed URL; the token fragment is exchanged for an HttpOnly SameSite=Strict cookie and removed from the address bar.
- Streamed PCAP/PCAPNG import, binary download and server capability reporting. Frontend feature pages share a transport-neutral bridge.
- Host allowlist, cross-origin protection, strict CSP, bounded body/concurrency/time limits and secret-free access logs. Remote binding requires an explicit address, `--allow-remote` and a TLS certificate/key.

## Verification and limits

See [0.5.0 verification](../verification/0.5.0.md), [C01](../verification/specs/C01.md), [W01](../verification/specs/W01.md), [W04](../verification/specs/W04.md) and [PLAN](../../PLAN.md). Local browser verification covers 30 tests, including a real HTTP server. Cross compilation and hosted builds do not establish native hardware acceptance.

Native SSH, alternate server-account/consent states, Edge/Chrome cross-origin manual acceptance, Linux/macOS hardware qualification, signing/notarization and remaining PLAN work stay open. This preview is not production qualified. The URL grants diagnostics, discovery, capture and saved Wi-Fi-key access as the server user: never share it. Windows archives may be available before hosted native platform archives complete; consult the release asset list and CI status.
