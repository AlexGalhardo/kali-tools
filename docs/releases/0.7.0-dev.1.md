# kali-tools 0.7.0-dev.1

**Status:** unsigned development preview; hardware qualification remains open. Not a release-qualified build.

## Changes

Work merged after 0.6.0-dev.2, from [#2](https://github.com/AlexGalhardo/kali-tools/pull/2) through [#18](https://github.com/AlexGalhardo/kali-tools/pull/18). The full entry is in the [changelog](../../CHANGELOG.md).

- Service inspection uses built-in TCP, banner and TLS checks. It does not run Nmap ([ADR 006](../adr/006-native-service-inspection.md)).
- DNS inspection, local mDNS/SSDP/SNMP discovery, HTTP phase timings and the documented HTTP contract are in the CLI, the API and the Diagnostics page.
- Capture summaries report truncation and a complete IPv6 hop-by-hop header. They do not reassemble TCP streams or IPv6 fragments.
- Linux baseline is Ubuntu 24.04 LTS. Debian 13 and Kali are best-effort. Routes and counters use netlink. Wi-Fi metadata uses nl80211. The saved key is read only through NetworkManager. Live capture can use libpcap with `CAP_NET_RAW` on the capture process.
- There is no privileged helper. Linux uses `sudo setcap cap_net_raw+eip`. macOS reports `access_bpf` and does not change device permissions. Windows points at a user-installed Npcap and does not bundle it ([ADR 011](../adr/011-no-privileged-helper.md)).
- `doctor --bundle` writes a local redacted zip. Nothing is uploaded. Schema version 1 fixtures and synthetic pcap, pcapng and CSV exports reopen without loss.
- macOS routes and counters read the routing sysctl. Current Wi-Fi uses CoreWLAN when cgo is enabled. Keychain lookup does not prompt ([ADR 013](../adr/013-macos-wifi.md)).
- The optional zcrypto legacy-protocol switch is deferred beyond 1.0. zlint still uses zcrypto only to parse certificates.

## First launch of an unsigned build

- **Windows:** SmartScreen may say the app is unrecognized. Choose **More info**, then **Run anyway**.
- **macOS:** Gatekeeper may block the app. Open **System Settings > Privacy & Security** and choose **Open Anyway**. If it stays blocked, clear the quarantine flag with `xattr -d com.apple.quarantine` on the `.app`.
- **Linux:** no extra first-launch prompt. Capture still needs a one-time `sudo setcap cap_net_raw+eip` on the capture binary. Do not run the UI or `kali-tools serve` as root.

## Verification and limitations

See [checkpoint verification](../verification/0.7.0-dev.1.md) and the [changelog](../../CHANGELOG.md). Artifacts are vendor-unsigned ([ADR 009](../adr/009-signing-and-provenance.md)). `BUILD.json` records `signed: false`. This is not a 1.0 build.

## Open native checks

These remain open. CI and cross-compilation do not close them.

- Ubuntu 24.04: a real Wi-Fi adapter, denied permission, restart, no saved PSK, and a libpcap capture after `setcap`. Debian 13 and Kali do not close the Linux baseline.
- Apple Silicon: CoreWLAN SSID and BSSID, Location Services for an ad-hoc build, the Keychain status of that build, and `access_bpf` after a new login. Do not change `/dev/bpf` permissions.
- Windows: a user-installed Npcap, elevated Pktmon only when that backend is selected, and the platform TLS verifier against an external endpoint. Pulling a cable stays on the Windows runbook.
- A person saving a diagnostic bundle on each OS, and clean-machine install, upgrade and rollback.
