# kali-tools 0.7.0-dev.2

**Status:** unsigned development preview; hardware qualification remains open. Not a release-qualified build.

## Changes

Work merged after 0.7.0-dev.1, from [#20](https://github.com/AlexGalhardo/kali-tools/pull/20) through [#24](https://github.com/AlexGalhardo/kali-tools/pull/24). The full entry is in the [changelog](../../CHANGELOG.md).

- `connections` lists Linux sockets with the owning process. A missing inode is omitted. Windows and macOS report `unsupported`. The table has no interface counters and no bandwidth estimate ([#20](https://github.com/AlexGalhardo/kali-tools/pull/20)).
- `throughput` exchanges bytes on `127.0.0.1` for 1ms..10s and reports the endpoint, duration and byte count. An iperf3 `-J` report can be parsed. iperf3 is not executed.
- The archive matrix is Windows x64, Ubuntu 24.04 x64 and macOS Apple Silicon. There is no installer. Deleting the unpacked directory leaves `history.db` in the per-user config directory ([#21](https://github.com/AlexGalhardo/kali-tools/pull/21)).
- CLI commands, HTTP routes, schema version 1, settings and that matrix are the frozen surface. kali-tools does not promise every Kali tool ([#22](https://github.com/AlexGalhardo/kali-tools/pull/22)).
- Install, accessibility and web-server threat-model notes are written. Those checks were not run ([#23](https://github.com/AlexGalhardo/kali-tools/pull/23)).
- The protected `release` environment is documented and was not created. This token received 403 ([#24](https://github.com/AlexGalhardo/kali-tools/pull/24)).

## First launch of an unsigned build

- **Windows:** SmartScreen may say the app is unrecognized. Choose **More info**, then **Run anyway**.
- **macOS:** Gatekeeper may block the app. Open **System Settings > Privacy & Security** and choose **Open Anyway**. If it stays blocked, clear the quarantine flag with `xattr -d com.apple.quarantine` on the `.app`.
- **Linux:** no extra first-launch prompt. Capture still needs a one-time `sudo setcap cap_net_raw+eip` on the capture binary. Do not run the UI or `kali-tools serve` as root.

## Verification and limitations

See [checkpoint verification](../verification/0.7.0-dev.2.md) and the [changelog](../../CHANGELOG.md). Artifacts are vendor-unsigned ([ADR 009](../adr/009-signing-and-provenance.md)). `BUILD.json` records `signed: false`. This is not a 1.0 build.

## Open native checks

These remain open. CI and cross-compilation do not close them.

- Ubuntu 24.04: a real Wi-Fi adapter, denied permission, restart, no saved PSK, and a libpcap capture after `setcap`. Compare `connections` with `ss`. Debian 13 and Kali do not close the Linux baseline.
- Apple Silicon: CoreWLAN SSID and BSSID, Location Services for an ad-hoc build, the Keychain status of that build, and `access_bpf` after a new login. Do not change `/dev/bpf` permissions. `connections` stays `unsupported` until a provider exists.
- Windows: a user-installed Npcap, elevated Pktmon only when that backend is selected, and the platform TLS verifier against an external endpoint. Pulling a cable stays on the Windows runbook. `connections` stays `unsupported`.
- A person saving a diagnostic bundle on each OS, and clean-machine install, upgrade, rollback and uninstall.
- Keyboard acceptance in English and PT-BR, and an external review of the web-server threat model.
- A repository admin still has to create the protected `release` environment. It is not configured.
