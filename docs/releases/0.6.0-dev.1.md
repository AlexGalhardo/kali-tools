# kali-tools 0.6.0-dev.1

Owner-requested checkpoint dated 2026-10-22. **Unsigned development preview; full PLAN and native qualification remain open.** Published releases and tags are unchanged.

## Changes

- Passive IPv4/IPv6 neighbor inventory in desktop, browser and CLI (`neighbors --family all|ipv4|ipv6 --format json|csv`). Windows uses the read-only OS cache; Linux uses netlink with a bounded procfs fallback. The UI adds translated state labels, filtering, refresh and pagination.
- Optional Npcap/Pktmon capture selection, capability status and packet-loss disclosures. Npcap is user-installed and not redistributed. Raw sockets remain the default; native acceptance of the optional backends is pending.
- Wi-Fi consent guidance and explicit retry, plus removal of partial Wi-Fi data from failed provider responses.
- Shared HTTP acceptance scenarios and additional server boundary checks.

## Verification and limitations

See [checkpoint verification](../verification/0.6.0-dev.1.md), [A01](../verification/specs/A01.md), [A06](../verification/specs/A06.md), [A05](../verification/specs/A05.md) and the [changelog](../../CHANGELOG.md). The private Linux Docker lab passes with the race detector. Both browser transports have 38 passing workflows in total.

Only Windows x64 binaries and source are packaged locally. No CI workflow is required or awaited. Linux Docker tests do not establish desktop or Linux/macOS hardware acceptance. Windows gateway/GUI comparison, optional capture runtime measurements, account/consent variations and signing/notarization remain open. No capture driver is installed and no real capture is started during this checkpoint. Artifacts disclose signed:false in BUILD.json.

B08 TLS audit is not implemented in this preview. Its dependency authorization and license review are preserved for continuation. This preview is not production qualified.
