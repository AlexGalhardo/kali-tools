# kali-tools 0.1.0-alpha.1-dev

Unsigned development preview of the Windows-first local network toolkit. This draft is not a qualified alpha release. See [the delivery plan](https://github.com/AlexGalhardo/kali-tools/blob/main/PLAN.md) and [changelog](https://github.com/AlexGalhardo/kali-tools/blob/main/CHANGELOG.md).

## Downloads

- Windows x64 ZIP: desktop EXE and CLI EXE; Windows 11 with Edge WebView2.
- Linux x64 tar.gz: desktop and CLI; Ubuntu 24.04 with GTK3/WebKitGTK 4.1.
- macOS x64 ZIP: Intel app bundle and CLI.
- macOS arm64 ZIP: Apple Silicon app bundle and CLI.
- Source archive, dependency inventory, third-party notices and `SHA256SUMS`.

Builds come from native GitHub runners after quality, security, browser and Docker checks pass. Each native archive includes `BUILD.json` with its source commit, version, platform and architecture. Verify SHA-256 checksums before running.

## Included

Interface inventory, counters, DNS record queries, TCP/HTTP/TLS diagnostics, Windows IPv4 ping/traceroute, scoped discovery, optional Nmap service signatures, SQLite preferences/history, PT-BR/English UI and bounded PCAP/PCAPNG import/export.

## Limits

Windows Wi-Fi key reveal and live capture still need hardware/permission acceptance. Live raw capture is IPv4-only, has no kernel drop count and requires administrator authorization. Key display is explicit and transient. Saving a packet file includes retained payloads; ordinary history excludes secrets, targets and payloads.

Linux/macOS Wi-Fi/capture providers and full native acceptance are incomplete. Packaging success does not establish feature parity. Nmap/TShark are separately installed; TShark execution is not implemented. Performance budgets, installers, signing and notarization remain open.

Project code uses the MIT license. Third-party components keep their own notices. The binaries have no trusted code signature and macOS previews are not notarized. No release tag or qualified release is created by the draft workflow.
